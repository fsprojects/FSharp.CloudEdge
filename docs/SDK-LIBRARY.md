# Library development

FSharp.CloudEdge combines server-side SDK bindings, shared support types and management
clients. [`config/sdk-delivery.json`](../config/sdk-delivery.json) selects the SDK libraries
generated by Xantham; Hawaii generates the management clients from OpenAPI. The
[scope table](SDK-DELIVERY-SCOPE.md) lists the selected libraries and package versions.
The broader inventory remains available for community extensions.

To use the published libraries, start with the [package guide](../site/content/guide/packages.md).
The commands below are for contributors regenerating and building the source hierarchy.

## Build

```sh
npm run build -- --plan
npm run build -- --resume
```

`build` generates the selected SDKs with the source adapter built from the pinned Xantham revision ([details](sdk-build.md)), generates management
from the pinned OpenAPI specification with Hawaii, and compiles the complete hierarchy in
`FSharp.CloudEdge.slnx`. Hawaii validates its staged Release build and local HTTP consumer
before installing generated files. `--resume` reuses SDK output only after authenticating
its inputs, catalogs, tool and source hashes. It also authenticates existing Hawaii output
against the generator package, schema, policies, overlays and owned files before reuse.
Pipeline and HTTP consumer source hashes are checked too; the installed ownership set must
match the staged run in full.
Compilation still runs.

`npm run build:sdk -- --resume` builds just the selected SDK/support hierarchy.
`npm run build:sdk -- workers containers` selects a smaller dependency closure.
`npm run build:sdk -- --all --plan` inspects the larger inventory; `--all` attempts it,
including integrations outside the default selection.

## Library hierarchy

| Directory | Contents |
|---|---|
| `src/Core` | Hawaii's shared API models |
| `src/Support` | Generated AI model contract owners and the handwritten Durable Object fetch adapter |
| `src/Runtime/Platform` | Native Workers resource declarations |
| `src/Runtime/Agents` | Agents, server MCP client, CodeMode, Shell and server Voice |
| `src/Runtime/AI` | AI Gateway, Workers AI, AI Search, AI Chat, AI Utils and Think |
| `src/Runtime/Compute` | Sandbox and Computer |
| `src/Runtime/Services` | Containers, Actors, Dynamic Workflows, OAuth and resource helpers |
| `src/Runtime/RPC` | Capnweb |
| `src/Runtime/FeatureFlags` | General and server Flagship APIs |
| `src/Runtime/Pages` | Cloudflare Access, Turnstile and Static Forms server middleware |
| `src/Management` | Hawaii clients grouped by service purpose |
| `src/Tenancy` | Hawaii account, membership and access-management APIs |

`FSharp.CloudEdge.Bindings.slnx` contains the selected generated hierarchy and its handwritten
Workers support project.
`FSharp.CloudEdge.slnx` also contains the consumer projects. `SDK.Partitions.slnx` and
`Hawaii.Bindings.slnx` expose the two generator pipelines separately.

## Exact scope and catalog injection

Each selected library lists its public imports explicitly. Omitted imports and whole
partitions have recorded reasons. Newly inventoried imports need an explicit selection.
Selection preserves each included declaration file's complete exports and
transitive type dependencies; it does not edit generated F# or prune difficult root members.
React, web clients, mobile UI, separate optional integrations and alternate preview surfaces
remain outside this selection. `agents/mcp/client` is retained as the server-side
`AgentsMcpClient` library.

`supportTargets` defines ordinary generated libraries for dependency types. `catalogImports` injects their authenticated declaration catalogs into consumers and orders producer generation before consumption. `inferenceProfiles` names one complete set of inference settings (`lib`, `types`, `groups`, `resolveNoInfer`), and a `targetOverrides` entry selects it with `inferenceProfile`. For example:

```json
{
  "catalogImports": {
    "containers": ["workers"],
    "aigatewayprovider": ["workers", "zod-v4", "json-schema-v7", "ai-provider-v4", "ai-provider-utils-v4", "ai-openai-compatible-v4"]
  },
  "inferenceProfiles": {
    "workers-node": {
      "lib": ["esnext"],
      "types": ["@cloudflare/workers-types", "node"],
      "groups": { "@cloudflare/workers-types": "ship", "@ai-sdk/provider": "ship", "zod": "ship" }
    }
  },
  "targetOverrides": {
    "workers": { "profile": "containers", "inferenceProfile": "workers-node" },
    "containers": { "inferenceProfile": "workers-node" }
  }
}
```

A catalog redirects a declaration only when the consumer generates that declaration itself, so an import requires the consumer to ship the producer's package and to share the producer's inference profile exactly. `scripts/sdk-delivery.mjs` rejects any other import before generation. The producer package must be directly pinned in its installation profile. A transitive dependency may be promoted at its existing locked version; doing so must retain resolved versions and tarball integrities. Catalog source and F# API checks remain enforced. The build authenticates owner provenance and derives the corresponding project references; sharing a package name alone is insufficient.

Every delivered library that reaches a shipped dependency package belongs to the single `workers-node` catalog family. The family generates with `lib: ["esnext"]`, `types: ["@cloudflare/workers-types", "node"]`, one `groups` map, and `@types/node` 26.4.1 in every family profile. Declaration identity includes every merged declaration with its package version, and `@types/node` augments the Workers web globals such as `Request`, `Response`, `URL` and `AbortSignal`, so a producer and consumer can share those declarations only with the same Node type pin. The Workers declarations therefore include those augmentations, such as the `URL` and `Console` heritage and the Node timer overloads. The pin is 26.x because `@types/node` 22.x adds script-level `compatibility/indexable.d.ts` declarations that move `Uint8Array` and the other typed arrays out of the compiler lib, which widens them to `obj`. Program contents outside the inference settings also gate reuse: a module augmentation (for example `@asteasolutions/zod-to-openapi` extending Zod in Chanfana's program) or a different package version produces different identities, and those declarations are generated locally in the consumer's group module.

Workers is the single owner of the ambient Workers declarations; there is no second generated Workers support assembly. AI Gateway and Workers AI retain AI SDK v4 model contracts. The pinned AI Search provider retains v3 contracts in a separate support library. These interfaces are not interchangeable. JSON Schema (`@types/json-schema` 7.0.15), Zod 4.5.4 (the `zod`, `zod/v3` and `zod/v4/core` declaration entries that consumers load), AI SDK provider utilities 5.0.36 and AI SDK 7.0.93 have their own generated support owners in the Agents profile; they are public dependencies of the libraries that reach them. Turnstile and Static Forms keep their DOM inference settings and import no catalogs; Voice errors and Cabidela reach no dependency declarations; Agents Pi keeps its own profile (Workers types `5.20261009.1` for wrangler 4.130.0) and its projection validation compiles without producer assemblies. The [composition consumer](../tests/SDKComposition/AI.fs) checks typed model selection and generation across these libraries. Exact npm dependencies are pinned in the corresponding `profiles/` lockfiles.

## Build output and fidelity

`artifacts/sdk-build/scope.json` records every selected and deferred public input.
`artifacts/sdk-build/targets.json` is the exact materialized generation configuration.
`artifacts/sdk-build/latest.json` records SDK generation and compilation;
`artifacts/library-build/latest.json` records the complete hierarchy build.
`artifacts/library-build/fidelity.json` presents the selected targets' symbol grades and
links to their detailed findings. Those per-target counts are not a deduplicated total
across the libraries.
Each target retains `manifest.json`, per-symbol findings, `declarations.json`, input
fingerprints and generation receipts under `artifacts/<target>/`.
SDK projects retain the existing `FS1104` suppression for generated identifiers containing
`@`. Compiler warning totals reflect that project setting; type-mapping losses remain
visible in the fidelity findings.

Use the fidelity findings to identify widened declarations and opaque boundaries that affect consumers. Consumer helpers belong in separate F# sources; generated files stay reproducible generator output. Resolve catalog source/API mismatches before introducing an injected type.

Generated bindings are constrained, contractual F# APIs that preserve the TypeScript contract across inputs, outputs, callbacks, properties, indexers, generic arguments and input/result relationships. A widened `obj` is a defect to repair in the owning generator pass or in catalog ownership, unless the source declaration itself is `any` or `unknown` and that source evidence is recorded. A renamed `obj`, an opaque wrapper over a lost contract, a dropped API or a lower aggregate finding count does not resolve a loss; the delivered inventory stays fixed while losses are repaired. A source contract that cannot be preserved is reported with its concrete limitation for an explicit decision.

There are two extension mechanisms. Generated support types use the catalog imports above,
which authenticate both ownership and the exposed F# API. Xantham also supports explicit
`groups` mappings from a TypeScript name to a supplied F# type and its generic arity. That
mapping is a caller-provided contract: the caller supplies the support library, project
reference and typed consumer checks. It does not establish catalog compatibility by itself.
Use a separate helper or support source for a deliberately narrowed boundary, and keep its
assumptions documented beside its consumer checks. Neither mechanism requires editing
generated bindings.

For callback injection, preserve the JavaScript calling convention with a named F#
delegate. A curried function alias can compile yet fail when invoking a returned
JavaScript callback. Expose `fun value count -> callback.Invoke(value, count)` when an F#
function interface is useful. Generic callback mappings can encounter the `TR053` arity
limitation; test the emitted JavaScript as well as compilation.

Some imported classes need a JavaScript adapter for subclassing. Direct F# subclassing of
`Container` is unsupported; the [Containers guide](../site/content/libraries/containers.md)
shows the adapter boundary. Agents, `AIChatAgent` and Think can expose imported base classes
as interfaces, so check the relevant [agent capability guide](../site/content/libraries/agents.md)
before implementing a subclass. Durable Object namespace `get`/`getByName` returns `obj`
for generic RPC stubs; `FSharp.CloudEdge.Support.Workers.DurableObjects.FetchTransport`
provides checked fetch forwarding without claiming arbitrary RPC typing.

Generation, compilation, typed composition and runtime behavior need separate checks.
Run hosted tests for service behavior, live inference and resource lifecycle.
The [integration guide](integration-testing.md) describes available diagnostics and planned
hosted coverage. [Durable Object tests](durable-objects-testing.md) cover subclassing,
typed storage, alarms and request forwarding.

## Retired local output

After a successful complete library build, archive generated directories left by the broader
inventory runs:

```sh
node scripts/archive-sdk-output.mjs --dry-run
node scripts/archive-sdk-output.mjs
```

The archive requires matching SDK and complete-library build evidence, verifies ownership
and source hashes, and checks retained project references. It moves eligible directories
into a dated `artifacts/sdk-output-archive/` directory with an inventory and build receipts.
Edited or unowned files are retained and reported. Canonical inventory configuration and
generation evidence remain available for subsequent opt-in builds.
